LBOB Phase 2

"The bot that knows you." — Actors & Personality

Phase 2 transforms LBOB from a stateless RAG chatbot into a personalized teacher. Each Telegram user gets a Dapr Virtual Actor — a persistent identity that remembers their practice level, adapts tone, and can proactively reach out with teachings.

Key change: openai-service splits into seeker-actor-service (per-user state, lifecycle, timers) and wisdom-service (stateless LLM + RAG). Actors call wisdom via Dapr service invocation, so LLM latency never blocks actor method calls.

Work Packages

WP1: SeekerActor
LP0

The core Dapr Actor representing each seeker. Holds practice level, tradition preference, conversation history, and topic exploration map.

  • Actor methods: receive_message, get_state, update_practice_level, set_tradition
  • State: chat_id, practice_level (newcomer→experienced), tradition, conversation_count, topics_explored, preferences
  • Uses trio.to_thread.run_sync for DaprClient calls (consistent with Phase 1)
  • Mock actor testing via dapr.actor.runtime.mock_actor
WP2: Wisdom Service
MP0

Extract LLM + RAG pipeline into standalone stateless service. Actors pass seeker context in; wisdom returns response + cited suttas + detected themes.

  • Moves rag.py + sutta_search.py from openai-service
  • Adaptive system prompt based on practice_level (newcomer gets definitions, experienced gets Pali)
  • Returns structured response: text + suttas_cited + detected_themes
  • Independently testable and scalable
WP3: Practice Level Detection
SP1

Heuristic scoring to detect practice level from conversation patterns. Vocabulary signals (Pali terms), question complexity, practice references, conversation count.

  • Level only goes UP — you don't un-learn the Dhamma
  • Requires 3+ signals at new level before promotion
  • Pure logic module — no infrastructure deps, can start immediately
WP4: Actor Timers
MP1

Proactive outreach via Dapr actor timers. Daily practice prompts, follow-up messages ("Last time we spoke about…"), and gentle return after 7+ days idle.

  • Timers survive container restarts (Dapr re-registers)
  • User opt-out: /silence and /remind commands
  • Callbacks must be idempotent (Dapr may fire >1x)
WP5: Compose & Infrastructure
MP0

compose.yaml, Dockerfiles, Dapr component config for new two-service topology. State migration script for existing users.

  • Remove openai-service containers, add seeker-actor + wisdom containers + sidecars
  • Actor idle timeout config, placement service
  • scripts/migrate_state_to_actors.py for existing seeker state
WP6: Telegram Updates
SP1

New bot commands: /start, /level, /tradition, /silence, /remind, /forget. Command interception before pub/sub.

Key Decisions

Skip Dapr Conversation API. Still alpha as of March 2026. Keep raw httpx to Anthropic proxy (ADR 0009). Revisit when it hits beta.
Multi-tradition = prompt variation only. Same wisdom service, different system prompt per tradition. Separate service-per-tradition is Phase 3 complexity.
Default Dapr placement service. Single-node deployment doesn't need a separate placement container. Add only if multi-node.
Clean state migration. One-time migration script, no backward compatibility layer. Run during deployment, delete old keys.
